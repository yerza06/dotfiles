# Quickshell status bar

Панель автоматически переключается между Flexoki Dark и Flexoki Light по значению `org.gnome.desktop.interface color-scheme`. Изменение применяется реактивно на обоих мониторах без перезапуска Quickshell.

Нативный `SystemTray` отображается перед батареей на обоих мониторах: ЛКМ активирует приложение, ПКМ открывает его меню, СКМ вызывает secondary action, колесо передаётся приложению.

Базовая панель для Niri на Quickshell 0.3.x.

## Запуск

```bash
qs -p ~/.config/quickshell/status_bars/shell.qml
```

## Пользовательский сервис systemd

Готовый unit-файл находится в общей директории сервисов Quickshell:

```text
~/.config/quickshell/services/quickshell_status_bars.service
```

Установка в системный каталог пользовательских unit-файлов:

```bash
sudo install -Dm644 \
  ~/.config/quickshell/services/quickshell_status_bars.service \
  /usr/lib/systemd/user/quickshell_status_bars.service
```

Перед первым запуском сервиса завершите вручную запущенную панель, чтобы не получить два экземпляра:

```bash
qs kill -p ~/.config/quickshell/status_bars/shell.qml
systemctl --user daemon-reload
systemctl --user enable --now quickshell_status_bars.service
```

Проверка:

```bash
systemctl --user status quickshell_status_bars.service --no-pager
journalctl --user -u quickshell_status_bars.service -b --no-pager
```

В `~/.config/niri/includes/startup.kdl` закомментируйте или удалите старую строку запуска status bar:

```kdl
// spawn-sh-at-startup "qs -p ~/.config/quickshell/status_bars/shell.qml"
```

Строку запуска `lang_switch` оставьте без изменений — это отдельная конфигурация Quickshell.

## Модули

- слева: Arch launcher (`fuzzel`), workspaces Niri и MPRIS;
- по центру: текущие дата и время (ЛКМ открывает календарь);
- справа: мониторинг системы, раскладка Niri, PipeWire (звук и микрофон), NetworkManager, Bluetooth, SystemTray и батарея UPower.

ЛКМ по значку мониторинга системы открывает `btop` в полноэкранном окне Kitty, ПКМ — окно с загрузкой CPU, памяти, диска, видеокарт, скоростью сети и аптаймом.

MPRIS показывает активный плеер и текущий трек. ЛКМ переключает play/pause, СКМ открывает окно медиаплеера, ПКМ — меню выбора плеера.

ЛКМ по звуку или микрофону включает/выключает mute, ПКМ открывает окно звука, СКМ — `pulsemixer` в Kitty, а колесо меняет громкость. ЛКМ по сети включает и выключает Wi-Fi, ПКМ открывает окно сети, СКМ — `nmtui` в Kitty. ЛКМ по Bluetooth открывает `bluetui`, ПКМ по Bluetooth открывает окно устройств, СКМ включает и выключает адаптер. ЛКМ по батарее переключает профиль питания по кругу, ПКМ открывает окно с подробностями.

### Подсказки при наведении

Наведение на мониторинг системы, сеть, Bluetooth или батарею показывает подсказку. Подсказка скрывается, пока открыто меню по ПКМ или любое окно — мониторинга, батареи, сети, Bluetooth или звука.

- **Сеть** — `Wi-Fi: <SSID>`, сила сигнала, тип защиты и IP-адрес; при кабеле — имя устройства, скорость линка и IP; иначе «Нет подключения» или «Wi-Fi выключен». Последние строки напоминают, что делают ЛКМ, ПКМ и СКМ.
- **Bluetooth** — список подключённых устройств с зарядом батареи, либо «Нет подключённых устройств» / «Выключен».
- **Батарея** — `Профиль: Эконом` / `Баланс` / `Мощность` с глифом профиля и напоминанием про ЛКМ и ПКМ. Если `power-profiles-daemon` сам снизил производительность, добавляется строка «Снижен: перегрев» или «Снижен: ноутбук на коленях» — иначе об этом узнать неоткуда.

IP-адрес `Quickshell.Networking` не предоставляет (в `device.address` лежит MAC), поэтому он запрашивается разово через `ip -j -4 addr show <устройство>` при наведении курсора и при смене активного устройства.

Все подсказки в панели рисует общий компонент `Tooltip.qml`: ширина и высота подбираются по содержимому, поэтому многострочные подсказки (сеть, Bluetooth) не обрезаются.

Закреплённый плеер хранится в `shell.qml` как `dbusName`, а не как ссылка на объект: строку не приходится чинить при выходе плеера, и она переживает его перезапуск, если имя шины стабильно (у Spotify это `org.mpris.MediaPlayer2.spotify`, у Firefox имя содержит номер инстанса и после перезапуска меняется — закрепление тогда возвращается к автовыбору). Состояние лежит в `ShellRoot`, а не в `Bar`, чтобы выбор был общим для всех мониторов.

### Меню по ПКМ

ПКМ по MPRIS открывает меню в стиле Flexoki. Меню закрывается через 400 мс после того, как курсор ушёл и с модуля, и с самого меню.

- **MPRIS** (`MprisMenu.qml`) — список запущенных плееров с названием текущего трека, у играющего `▶`. Клик закрепляет плеер: панель показывает и управляет именно им, пока он запущен. Пункт «Автовыбор» возвращает поведение по умолчанию — первый играющий, иначе первый в списке. Последней строкой «Следующий трек» (появляется, только если плеер это умеет); меню при этом не закрывается.

Строки меню и окон рисует общий делегат `DeviceRow.qml`. Окно Bluetooth рисует свой `BluetoothDeviceRow.qml`: общему делегату понадобились бы глиф типа, полоса заряда и раскрытие, а у него уже пять потребителей.

### Календарь

ЛКМ по часам открывает календарь (`ClockItem.qml` + `CalendarPopup.qml`): крупные дата и время сверху, ниже сетка месяца с понедельника. Сегодняшний день залит акцентным цветом, суббота и воскресенье выделены красным, дни соседних месяцев приглушены.

Месяцы листаются стрелками `‹` `›`, колесом над сеткой и клавишами `←` `→` (`PageUp` и `PageDown` — на год). Клик по названию месяца и `Home` возвращают к текущему. В сетке всегда шесть строк, поэтому при листании окно не меняет высоту.

В отличие от меню по ПКМ, календарь не закрывается по уходу курсора: только повторным ЛКМ по часам, кликом мимо или `Esc`. За клик мимо отвечает `grabFocus` у `PopupWindow` — окно закрывает сам композитор. Поэтому `visible` у календаря выставляется вручную, а не биндингом: после первого внешнего закрытия биндинг бы сломался. Ради `Esc` панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока календарь открыт.

### Медиаплеер

СКМ по модулю MPRIS открывает окно плеера (`MprisPopup.qml` + `MprisControlButton.qml`): обложка трека, название, исполнитель и альбом, прогресс-бар и пять кнопок — перемешивание, предыдущий, play/pause, следующий, повтор. Управляется тот же плеер, что показан в панели, то есть закреплённый через меню по ПКМ или выбранный автоматически.

Обложка берётся из `trackArtUrl`; пока она не загрузилась или её нет вовсе, вместо картинки показан глиф плеера — тот же, что в панели. Ширина окна фиксирована, поэтому длинный заголовок с YouTube не распирает его при смене трека.

Перемешивание и повтор работают как в Spotify: включённый режим красится акцентным цветом, выключенный — приглушённым. Повтор перебирается по кругу «выключен → плейлист → трек», и в режиме трека глиф меняется на вариант с единицей. Обе кнопки гаснут у плееров, которые не отдают `shuffleSupported` и `loopSupported` — например, у Firefox.

Прогресс-бар перематывает кликом и перетаскиванием, если плеер отдаёт `canSeek`; иначе остаётся индикатором. Позиция у `MprisPlayer` вычисляется при чтении и сама об изменении не сообщает, поэтому раз в секунду `positionChanged()` эмитится вручную — только пока окно открыто и идёт воспроизведение. Во время перетаскивания полоса рисуется от позиции под курсором, иначе она отскакивала бы назад в момент отпускания: плеер сообщает новую позицию не мгновенно. Кнопки гаснут и перестают нажиматься, когда плеер не поддерживает соответствующее действие.

Окно ведёт себя как календарь, а не как меню по ПКМ: не закрывается по уходу курсора, только повторным СКМ, кликом мимо или `Esc`. Клавиши: `Пробел` — play/pause, `←` `→` — предыдущий и следующий трек, `S` — перемешивание, `R` — повтор. Ради них панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока окно открыто. Окно плеера и меню по ПКМ взаимно исключают друг друга.

### Звук и микрофон

ПКМ по звуку или микрофону открывает окно (`VolumeItem.qml` + `AudioPopup.qml`): крупный глиф, название текущего устройства PipeWire по умолчанию с подписью «Устройство вывода» или «Устройство ввода», круглая кнопка mute, полоса громкости с процентом и список устройств для переключения с отметкой `●` у текущего. Последней строкой `pavucontrol`.

Оба модуля обслуживает один и тот же компонент — вывод от ввода отличает только `microphoneMode`, от него зависят и подписи, и то, какие узлы попадают в список: sink'и или source'ы. Потоки приложений отсеиваются, а флаги типа проверяются побитово, чтобы дуплексные карты попадали и в вывод, и в ввод.

Глиф и процент считает `VolumeItem` и передаёт в окно — панель и окно всегда показывают одно и то же, включая тип выхода (наушники, HDMI) и красный при mute. Полоса перетаскивается и ограничена 100 %; колесо мыши по-прежнему поднимает громкость до 150 %, и заливка при этом просто упирается в край дорожки. При наведении без клика показывается подсказка с процентом и именем устройства.

Окно ведёт себя как календарь и плеер: не закрывается по уходу курсора, только повторным ПКМ, кликом мимо или `Esc`. Клавиши: `Пробел` и `M` — mute, `←` `→` — громкость на 5 %. Ради них панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока окно открыто. Выбор устройства окно не закрывает — так виден результат переключения.

### Мониторинг системы

Прежние пилюли CPU и RAM заменены одним значком `` (`SystemMonitorItem.qml`). Цифр в самой панели нет: ЛКМ открывает `btop` в полноэкранном окне Kitty, ПКМ — окно мониторинга (`SystemMonitorPopup.qml` + `SystemMetricRow.qml`).

В шапке окна — load average за 1/5/15 минут, ниже строки с процентом и полосой:

- **CPU** — загрузка и температура пакета (`coretemp`/`k10temp`);
- **RAM** — занято и всего, «занято» считается как `MemTotal − MemAvailable`;
- **DISK** — корневой раздел; процент как у `df` — от места, доступного пользователю;
- **GPU1** и **GPU2** — видеокарты в порядке PCI-адресов, то есть сначала встроенная Intel, затем NVIDIA. Под строкой — модель, у NVIDIA ещё и занятая видеопамять. У Intel рядом с процентом частота, у NVIDIA — температура;
- **NET** — скорость приёма и отдачи по всем физическим интерфейсам, без полосы;
- **UPTIME** — время с загрузки из `/proc/uptime` с точностью до минуты (`2 д 3 ч 12 мин`), без полосы.

Полоса синяя до 70 %, оранжевая до 90 % и красная выше. Строка «btop…» внизу открывает тот же `btop` и закрывает окно.

Данные собирает `scripts/system-monitor.sh` — раз в секунду одна строка JSON. Скрипт запускается, только пока окно открыто: раз в панели цифр нет, опрашивать систему в фоне незачем. Перед первой строкой он делает затравочный замер, чтобы проценты появились сразу, а не через секунду с нулями.

- Загрузка Intel (`i915`) считается по `gt/gt0/rc6_residency_ms`: доля времени, которую GPU провёл вне сна RC6, — то же, что показывает `intel_gpu_top`, но без root.
- NVIDIA на ноутбуке большую часть времени спит в runtime suspend. `nvidia-smi` её будит, и потом она долго не засыпает, поэтому скрипт сначала читает `/sys/bus/pci/devices/<адрес>/power/runtime_status` и спящую карту не трогает — в окне тогда «сон» и пустая полоса. Имена моделей по той же причине берутся из `pci.ids` по `vendor`/`device` из sysfs, а не через `lspci`: он читает конфигурационное пространство и тоже будит карту.
- Трафик суммируется только по интерфейсам с `/sys/class/net/<имя>/device`: у `lo`, veth, мостов и туннелей его нет, а их трафик и так проходит через физический интерфейс.

Окно ведёт себя как окна сети и батареи: не закрывается по уходу курсора, только повторным ПКМ, кликом мимо или `Esc`. Ради `Esc` панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока окно открыто.

### Батарея

ПКМ по батарее открывает окно (`BatteryItem.qml` + `BatteryPopup.qml` + `BatteryProfileButton.qml`): крупный глиф с состоянием и процентом, полоса заряда, остаток времени, текущий заряд с ёмкостью, здоровье и число циклов, переключатель профиля питания и текущее потребление в ваттах.

ЛКМ по батарее переключает профиль по кругу в том же порядке, что и кнопки в окне: Эконом → Баланс → Мощность. При наведении подсказка показывает текущий профиль — отдельного значка профиля в панели больше нет.

Глиф, процент и цвет считает `BatteryItem` и передаёт в окно — панель и окно всегда показывают одно и то же, включая красный при 0–15 % и оранжевый при 16–30 %.

В самом окне профиль питания переключается тремя кнопками «Эконом», «Баланс», «Мощность» (или клавишами `1` `2` `3`); активный выделен рамкой и цветом. «Мощность» гаснет, если `power-profiles-daemon` не отдаёт `hasPerformanceProfile`. Отдельного значка профиля в панели больше нет — его роль забрало это окно.

Потребление показано с точностью до десятых: при разрядке оранжевым, при зарядке зелёным, при неизвестной величине — прочерком.

Окно ведёт себя как календарь и окно плеера: не закрывается по уходу курсора, только повторным ПКМ, кликом мимо или `Esc`. Ради `Esc` панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока окно открыто.

Порог заряда (`charge_control_end_threshold`) в окно не выведен: запись в него требует прав root.

### Сеть

ПКМ по сети открывает окно (`NetworkItem.qml` + `NetworkPopup.qml`): шапка с именем сети и тумблером Wi-Fi, пинг и потери до `1.1.1.1`, скорость приёма и отдачи, объём трафика, IP-адрес и шлюз, затем списки `ИЗВЕСТНЫЕ СЕТИ` и `ДОСТУПНЫЕ СЕТИ`, последней строкой «Настройки сети…» (`nmtui`). Клик по известной сети подключает, по подключённой — отключает, по незнакомой защищённой — открывает поле ввода пароля (Enter подключает, Esc отменяет). Пока окно открыто, работает сканирование эфира.

ЛКМ по сети включает и выключает Wi-Fi (`Networking.wifiEnabled`), СКМ открывает `nmtui` в Kitty. Окно ведёт себя как календарь: не закрывается по уходу курсора, только повторным ПКМ, кликом мимо или `Esc`.

### Bluetooth

ПКМ по Bluetooth открывает окно устройств (`BluetoothItem.qml` + `BluetoothPopup.qml` + `BluetoothDeviceRow.qml`): в шапке имя адаптера, его состояние и тумблер, ниже «Видимость» и «Разрешить сопряжение», затем списки `ПОДКЛЮЧЕНО` и `ДОСТУПНО`, последней строкой `bluetui`. ЛКМ по-прежнему открывает `bluetui`, СКМ включает и выключает адаптер.

Окно показывает только сопряжённые устройства: `ДОСТУПНО` — это сопряжённые, но отключённые. Сканирования эфира, сопряжения и удаления в окне нет намеренно — это остаётся за `bluetui`, поэтому `adapter.discovering` окно не трогает и радио зря не жжёт.

Клик по строке подключает или отключает устройство; окно при этом не закрывается — виден переход `◐` и результат. У каждой строки свой глиф по типу устройства (`device.icon` от BlueZ): гарнитура, наушники, клавиатура, мышь, геймпад, телефон, принтер, камера, иначе общий значок Bluetooth. Справа — заряд, если BlueZ его отдаёт, иначе состояние.

Шеврон справа раскрывает настройки устройства: полоса заряда, переключатель «Доверенное устройство», поле переименования и MAC-адрес. Раскрыт всегда только один блок, и хранится он по адресу устройства, а не по ссылке: список пересоздаётся при каждом обновлении модели, а `bluetui` может удалить устройство прямо при открытом окне. Полоса заряда красная до 15%, оранжевая до 30% и зелёная выше — пороги те же, что у батареи, но зелёный там занят зарядкой, а у Bluetooth-устройства состояния «заряжается» нет.

Переименование пишет в `device.name` — это `Alias` в BlueZ, единственное записываемое имя; `device.deviceName` (`Name`) только для чтения. Поэтому и метка устройства берёт сначала `name`: с обратным порядком новое имя не было бы видно. Пустое имя не применяется — BlueZ сбросил бы алиас к заводскому. Поле не перехватывает фокус при раскрытии: строку чаще раскрывают ради заряда и доверия, и случайный Enter переименовывал бы устройство.

Окно ведёт себя как календарь и окно сети: не закрывается по уходу курсора, только повторным ПКМ, кликом мимо или `Esc`. `Esc` двухступенчатый — сначала сворачивает раскрытую строку, потом закрывает окно. Ради `Esc` и ввода имени панель берёт клавиатуру (`WlrKeyboardFocus.OnDemand`), пока окно открыто.

Тумблер адаптера гаснет и не нажимается, когда адаптер заблокирован через rfkill: запись в `enabled` всё равно молча провалилась бы по DBus. «Видимость» BlueZ снимает сам по `discoverableTimeout`, поэтому тумблер может вернуться в исходное положение — он привязан к живому свойству.

### Источники данных

Мониторинг системы — `/proc`, sysfs, `df` и `nvidia-smi` через `scripts/system-monitor.sh`. Звук — `Quickshell.Services.Pipewire`, Bluetooth — `Quickshell.Bluetooth` (BlueZ), сеть — `Quickshell.Networking` (NetworkManager). Форматтеры сети и Bluetooth вынесены в синглтоны `NetworkFormat.qml` и `BluetoothFormat.qml`, чтобы виджет в панели не дёргал их у меню. У адаптера Bluetooth в Quickshell 0.3.1 нет MAC-адреса (`BluetoothAdapter` отдаёт только `name`, `adapterId` и `dbusPath`), поэтому в шапке окна стоят имя и `hci0`. Заряд устройства приходит из `org.bluez.Battery1` числом 0..100. Опроса `nmcli` по таймеру нет: состояние приходит реактивно по DBus.

Батарея — `Quickshell.Services.UPower`. Процент, состояние, остаток времени, текущий заряд и потребление берутся у `UPower.displayDevice`, но это синтетическое устройство-агрегат: `Capacity` и `NativePath` у него пустые. Поэтому здоровье читается у настоящей батареи из `UPower.devices` (по `isLaptopBattery`), а число циклов — разовым `cat /sys/class/power_supply/<NativePath>/cycle_count` при открытии окна: `ChargeCycles` в D-Bus есть, но Quickshell 0.3.1 его в QML не пробрасывает. Профили питания — синглтон `PowerProfiles` из того же модуля.

Иконка сети выбирается по типу устройства, а не по имени соединения: кабель имеет приоритет над Wi-Fi, поэтому при подключении по Ethernet или USB-тетерингу показывается иконка Ethernet даже при активном Wi-Fi.

При заряде 16–30% аккумулятор каждые 500 мс переключается между оранжевым фоном с тёмным текстом и тёмным фоном с оранжевым текстом. При критическом заряде 0–15% он каждые 380 мс переключается между красным фоном с тёмным текстом и тёмным фоном с красным текстом. Во время зарядки и выше 30% мигание отключено.
